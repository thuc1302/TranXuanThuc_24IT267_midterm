## 1. Project overview

The purpose of this project is to implement a **simplified Unix `ls` command** in the C programming language, using filesystem system interfaces instead of calling the system's `ls` command. The project demonstrates:

- Scanning directory entries with `opendir()`, `readdir()`, and `closedir()`.
- Reading file metadata using `lstat()` and `stat()`.
- Handling symbolic links via `readlink()`.
- Processing command-line arguments using `getopt_long()`.
- Sorting records, formatting permissions, owners, groups, dates, and sizes.
- Handling invalid paths and permission errors while continuing with other inputs.
- Traversing directory trees recursively using an **explicit heap-allocated stack**.

This project was written for Linux/Ubuntu (POSIX-style interfaces; a few Linux-specific headers).

## 2. Supported features and options

| Option | Implemented behavior |
|---|---|
| *(no option)* | List non-hidden directory contents, sorted by name, one per line |
| `-a` | Include all hidden entries, including `.` and `..` |
| `-A` | Include hidden entries but exclude `.` and `..` |
| `-l` | Long format: file type/permissions, hard-link count, user, group, size, modification date, name; symbolic-link targets |
| `-h` | Human-readable sizes with `-l` or `-s` |
| `-R` | Recursively list directories |
| `-r` | Reverse the listing order |
| `-t` | Sort by modification time (newest first) |
| `-S` | Sort by file size (largest first) |
| `-U` | Keep directory enumeration order instead of sorting |
| `-1` | One entry per line; cancels an earlier `-l` |
| `-d` | Show directory names themselves instead of opening them |
| `-i` | Show inode numbers |
| `-F` | Append indicators (`/`, `@`, `*`, `|`, `=`) for file types |
| `-p` | Append `/` to directory names |
| `-s` | Display allocated disk usage in 1 KiB blocks |
| `-n` | Long format with numeric user and group IDs |
| `--help` | Display usage instructions |
| `--` | Stop option parsing; useful for paths beginning with `-` |

You can combine options: `-lah`, `-laR`, `-ltr`, `-Sh`, etc. When more than one sorting mode is requested, the **last** of `-t`, `-S`, or `-U` takes effect. Options should precede pathname operands.

### Important limits of this simplified implementation

- **Output is always one file per line.** It intentionally does not implement terminal-width-dependent multi-column layout, even without `-1`.
- Long output is legible but is not guaranteed to match GNU `ls` byte-for-byte regarding widths, ACL/SELinux indicators, quoting, or time rules.
- Not all GNU `ls` flags or GNU long options are supported. Unsupported options produce an error.
- Block sizes are reported in 1 KiB units (POSIX `st_blocks` is based on 512-byte blocks).
- Recursive descent does not follow symbolic links discovered inside directories. This prevents loops.
- Unreadable or missing entries are reported on standard error and cause nonzero exit status.

## 5. Design and algorithms

**Command-line processing (`options.c`).** The parser uses `getopt_long` and a shared `LsOptions` structure. Unknown options are rejected with an error status. No shell commands or external `ls` program are executed.

**File and directory reading (`entries.c`).** For each operand, file metadata is read and it is placed in either the files group or directories group. Directory contents are collected using `readdir`. Entries beginning with `.` are filtered unless `-a` or `-A` is given. `lstat` is used for directory entries to preserve symbolic-link information.

**Sorting (`entries.c`).** `qsort()` and `strcoll()` sort by name. With `-t`, the modification timestamps (including nanoseconds) are sorted newest-first; with `-S`, sizes are sorted largest-first. Matching values fall back to name order. `-r` reverses that result.

**Output (`display.c`).** In long mode, permission bits are converted to symbolic characters such as `drwxr-xr-x`. The program looks up users and groups with `getpwuid` and `getgrgid`, or prints numeric IDs for `-n` or unknown IDs. `readlink` displays a symbolic link's target. File sizes and timestamps are formatted for reading.

**Recursion (`listing.c`).** For `-R`, an explicit resizable stack handles directories without unbounded C function recursion. Subdirectories are pushed in reverse sorted order, which preserves the chosen output order. `.` and `..` are never descended into.

**Error handling.** Path operations check return codes and print descriptive errors. When one operand fails, remaining operands are still processed. Dynamic allocation helpers check for allocation failure. The exit code is 0 for success, 1 for filesystem errors, or 2 for invalid options.
